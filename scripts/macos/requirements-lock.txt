# Versões validadas para o espetáculo em macOS arm64 com Python 3.13.

# NOTA sobre o opencv-python ausente (Problema 1 do endurecimento pré-evento):
# o pyvidplayer2 declara opencv-python como dependência de instalação, mas só o
# importa em runtime se `importlib.util.find_spec("cv2")` o encontrar — e nesse
# caso prefere-o ao FFMPEGReader para ler vídeo local. O wheel do opencv-python
# (e também o opencv-python-headless, testado e confirmado com o mesmo problema)
# traz o seu próprio libSDL2-2.0.0.dylib, que colide em runtime com o do pygame:
# "Class SDLApplication is implemented in both ... This may cause spurious
# casting failures and mysterious crashes." — o pior cenário possível a meio
# do evento.
#
# Não instalar opencv aqui é deliberado: sem cv2, o pyvidplayer2 cai sozinho
# para o FFMPEGReader (ffmpeg já é dependência do projeto), sem perder
# funcionalidade — confirmado a decodificar os clips PT reais via
# TvShowResources.init(), os 4 quadrantes, sem o aviso objc duplicado.
# setup.sh instala este ficheiro com `--no-deps`, precisamente para que o
# resolvedor do pip não volte a puxar o opencv-python como dependência
# transitiva do pyvidplayer2. Nunca reintroduzir opencv-python(-headless)
# neste .venv sem repetir essa validação.
